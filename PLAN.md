# AutoClaw.Z.ai-ExportChat — GUI-надстройка. План работ для ZCode

> **АРХИВ (2026-11-15, раунд 19).** Исторический документ этапа «CLI-движок / два exe» — описанная архитектура устарела. Актуальное состояние проекта: `README.md` / `README.ru.md` / `README.zh.md`; журнал решений: `AGREEMENTS.md` (раунды 1–20). Сохранён как история проектирования.


Версия плана: 1.5 (2026-11-06).
Автор плана: AutoClaw (владеет «нижним уровнем» — CLI-движком).
Исполнитель GUI: ZCode.

## 1. Что это за проект

AutoClaw.Z.ai-ExportChat — утилита, которая читает локальную базу AutoClaw
(только чтение) и сохраняет диалог в один файл: Markdown, TXT или JSON.
Репозиторий: https://github.com/vadimrm/AutoClaw.Z.ai-ExportChat

Сейчас это CLI: пользователь вызывает `export_chat.py` ключами.
Задача этого проекта — сделать **GUI-приложение**, в котором всё, что
задаётся ключами, выбирается чекбоксами, кнопками и списками.

Правила по зонам:

- **README в корне** описывает весь проект: раздел GUI обновляет ZCode,
  раздел про движок — только по согласованию.

  по согласованию обеих сторон.

### Публикация в GitHub — обязанность ZCode

Цикл обновления движка:

1. AutoClaw кладёт новый `export_chat.py` в `C:\zcode_prj\z5_autoclaw_dir`.
2. ZCode копирует его в `backend/`, прогоняет smoke-тесты (см. п.9).
3. ZCode коммитит и пушит всё вместе (движок + GUI) одним релизом.
4. При значимых изменениях — тег и Release.

## 3. Как GUI вызывает движок

Коротко (полная спецификация — `API_CONTRACT.md`):

```
python backend/export_chat.py /list /api            -> JSON-массив диалогов в stdout
python backend/export_chat.py /chat <id|title> /out <файл> /api
                                                    -> JSON {ok, path, requests}
python backend/export_chat.py /all /dir <папка> /format json /api
                                                    -> JSON {ok, dir, exported: [...]}
python backend/export_chat.py /ver                  -> текст версии
```

- Ошибки: в `/api`-режиме JSON уходит в stderr, код выхода 1.
- Ключи движка начинаются с `/`; ключи с `-` и `--` запрещены и дают ошибку.
- Кодировка: файлы md/txt создаются с BOM, json — без BOM (это уже делает
  движок, GUI не должен ничего дописывать).
- Важно: пути с пробелами передавать одним аргументом (subprocess list).

## 4. Требования к GUI

1. Windows 10/11, без прав администратора.
2. Русский интерфейс по умолчанию; переключатель языка ru/en/zh (как /lang).
3. Элементы управления — зеркала ключей движка:
   - список диалогов -> /list (обновление по кнопке);
   - выбор диалога -> /chat;
   - формат -> /format md|txt|json;
   - папка вывода -> /out или /dir;
   - «включить инструменты» -> /tools;
   - «показать служебные файлы» -> /all-files;
   - «скрыть блоки файлов» -> /no-files;
   - лимит результата инструментов -> /tool-limit;
   - «без BOM» -> /no-bom;
   - база вручную -> /db.
4. Прогресс и результат: после экспорта показывать путь к файлу и кнопку
   «Открыть папку».
5. Автообнаружение базы: искать runtime.sqlite по стандартным путям
   (как делает движок); возможность указать путь вручную.
6. Ошибки движка показывать пользователю текстом из stderr.
7. Никакого чтения SQLite из GUI — только через движок.

## 5. Окружение и зависимости

- В комплекте AutoClaw идёт Python 3.13 **без tkinter** — обычный Tkinter
  на нём не заработает.
- GUI-пакеты ставить в отдельный venv, не в системный Python и не в
  интерпретатор AutoClaw.
- Целевая поставка: один .exe (PyInstaller) рядом с export_chat.py, либо
  папка с запуском через venv — вариант выберется по п.6.
- WebView2 Runtime предустановлен на Win10/11 с Edge, но не гарантирован
  на «чистых» системах — если выбор падёт на webview, учесть fallback.

### 6.1 Варианты, уже проанализированные AutoClaw

Движок вызывается как внешний процесс (см. `API_CONTRACT.md`), поэтому выбор
GUI-технологии **не влияет на backend** — оценивайте только GUI.

| Вариант | Поставка | Зависимости | Комментарий AutoClaw |
|---|---|---|---|
| PySide6 (Qt) | .exe ~60–80 МБ | PySide6 в venv | нативное окно, самодостаточно; тяжёлый exe |
| pywebview + WebView2 | .exe ~12–15 МБ | WebView2 (есть в Win10/11 с Edge) | нативное окно + HTML-интерфейс; на «чистых» системах нужен Evergreen-установщик |
| Локальный веб-UI (stdlib http.server) | .exe ~7 МБ | нет | интерфейс — вкладка браузера на 127.0.0.1; проще всего |
| C# WinForms (csc.exe из .NET Framework 4.8) | .exe ~150 КБ | нет | крошечный нативный exe; SQLite не нужен — данные через движок |
| Tkinter | — | — | НЕДОСТУПЕН: в Python из AutoClaw нет tkinter (проверено) |
| Electron | 150+ МБ | node | избыточно |

Факт для планирования: системный Python не обязателен — движок (stdlib-only,
3.10+) работает на любом интерпретаторе, который выберет GUI.

### 6.3 Когда подключается AutoClaw

Выбор фронтенд-стека ZCode обсуждает с пользователем напрямую. AutoClaw
(владелец движка) подключается только если выбранный вариант требует
изменений в движке. Единственный известный кандидат — **прогресс
выполнения** во время долгого экспорта (сейчас движок молчит до конца);
если GUI захочет прогресс-бар — это запрос в `ENGINE_REQUESTS.md`.
Остальное (пути, форматы, BOM, имена файлов) движок уже умеет.
