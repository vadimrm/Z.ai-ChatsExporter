Критерии выбора (по убыванию важности, из п.6 плана):

Общее для всех вариантов:

- Движок **не меняется**: `backend/export_chat.py` копируется без изменений и
  замораживается в `ExportChat-engine.exe` (~7–10 МБ, stdlib), GUI вызывает
  его как внешний процесс по `API_CONTRACT.md` (коды 0/1/2, JSON, `/lang`).
  Опция для веб-UI и Tkinter: один exe с диспетчерским флагом (GUI-процесс
  перезапускает сам себя в режиме движка) — файл движка по-прежнему не меняется.
- Долгий `/all` — неблокирующе, неопределённая индикация (движок молчит до конца).
- Конфиг: `%APPDATA%\AutoClaw\Z.ai-ExportChat-GUI\config.json`; «Открыть папку» —
  `explorer.exe /select,"<путь>"`.
- Могу ли я сам собрать exe на этой машине без платного ПО и без админ-прав —
  **да, во всех четырёх вариантах**: Python 3.12.10 + pip уже есть, csc.exe уже
  в ОС, всё остальное ставится в venv в профиль пользователя.

## 2. Отклонённые варианты (из анализа 1.0)

- **pywebview + WebView2** — проигрывает по главному критерию: WebView2 не
  гарантирован на «чистых» системах (fallback — Evergreen-установщик); плюс мост
  Python↔JS и pythonnet. Слабее всех живых вариантов по кр.1.
- **Electron** — 150+ МБ и Node-тулчейн, избыточен.
- **Tkinter «недоступен»** — ограничение относилось к интерпретатору AutoClaw;
  снято в v1.1 (см. шапку).

## 3. Финалист A: PySide6

|---|---|
| Стек | Python 3.12/3.13 (свой venv) + PySide6-Essentials (LGPL), сборка PyInstaller |

## 7. Рекомендация (обновлена в 1.1)

- **По критериям плана (взвешенно 4/3/2/1) теперь лидирует Tkinter**:
  надёжность нативного окна, вся разработка на stdlib, поставка на порядок
  меньше PySide6, разработка быстрая. Плата — сдержанный внешний вид ttk
  и ручной фильтр таблицы.
- **PySide6** — выбор, если важнее современный вид и максимально готовые
  механизмы (модель/вид, фильтр, i18n), ценой поставки ~70–90 МБ.
- **C# WinForms** — минимальная поставка (~8–10 МБ), но медленнейшая
  разработка и проприетарный in-box компилятор (свободная альтернатива
  Roslyn есть, но требует установки SDK).
- **Локальный веб-UI** — быстрейший MVP, но UI в браузерной вкладке.

Решение — за пользователем. Код GUI до выбора не пишется (п.6.2).
Сборки до согласования не распространяются (п.10 плана).
