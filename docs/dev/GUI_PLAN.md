## 0. Зафиксированные решения

| Решение | Выбор |
|---|---|
| Фронтенд | Tkinter/ttk (тема «vista»), чистый stdlib, сборка PyInstaller |
| Поставка v1 | zip с двумя exe: `ExportChat-GUI.exe` (~12–15 МБ) + `ExportChat-engine.exe` (~7–9 МБ). Один exe-диспетчер (~−8 МБ) — опция после v1; точка расширения заложена в `main.py` сразу |
| Движок | копия `backend/export_chat.py` **без изменений**; в разработке — запуск исходника, в поставке — engine exe |
| Выбор диалога | экспорт только по `id` из `/list` (не по названию — исключает `err_ambiguous`) |
| Папка вывода (один диалог) | `/out` не передаётся: движок запускается с `cwd=папка вывода` и сам строит стандартное имя `AC-…` — правила имён остаются у движка, результат идентичен CLI |
| Папка вывода (все) | `/dir <папка>` + `/format` |
| Тесты | обычные python-скрипты с assert (без pytest), запускаются из Bash |
| Зависимости GUI | ноль сторонних; pyinstaller — только в отдельном сборочном venv |

## 1. Архитектура

### 1.1 Структура

```
<корень репо>/
├── backend/export_chat.py        # копия движка (зона AutoClaw, не редактируется)
├── frontend/
│   ├── main.py                   # вход: DPI-настройка, окно; точка входа worker-режима (опция)
│   ├── app.py                    # App: компоновка grid, события, состояние
│   ├── engine_client.py          # subprocess-обёртка + фоновый поток
│   ├── i18n.py                   # STRINGS ru/en/zh, tr(), set_lang()
│   ├── config.py                 # Config, load/save (%APPDATA%)
│   └── tests/
│       ├── test_engine_smoke.py  # шаг 1: контракт
│       ├── test_units.py         # шаги 2–3: config/i18n/engine_client
│       └── gui_selftest.py       # шаг 4: окно строится, языки, argv
└── build/
    ├── engine_shim.py            # вход engine exe: импорт export_chat, main()
    ├── gui.spec                  # spec GUI (noconsole)
    └── build.bat                 # venv → pyinstaller → release/
```

### 1.2 Модель потоков

- Один GUI-поток (Tk). Работа с движком — в фоновом потоке, **не более одной задачи**;
  результат — через `queue.Queue`, опрос `root.after(100)`; из потока Tk не трогается никогда.
- Во время задачи: кнопки действий disabled, в статус-баре неопределённый прогрессбар
  («движок молчит до конца» — детерминированный прогресс потребовал бы изменения движка).
- Закрытие окна во время задачи: подтверждение → `terminate()` процесса движка.
- Таймауты: `/list` 60 с, `/chat` 120 с, `/all` 600 с; по таймауту — kill + сообщение.

### 1.3 Маппинг «элемент интерфейса → ключ движка»

| Элемент | Ключ/поведение |
|---|---|
| Таблица диалогов + «Обновить» | `/list /api` (id, title, даты, requests) |
| Поле поиска | локальный фильтр по названию, без движка |
| Выбор строки | id для `/chat` |
| Кнопки «Экспорт в MD/TXT/JSON» | `/chat <id> /format <f> /api`, cwd = папка вывода |
| «Экспортировать все» | `/all /dir <папка> /format <f> /api` |
| Формат (combobox) | `/format md\|txt\|json` (для «все»; кнопки синхронизируют) |
| «Инструменты» | `/tools` |
| «Промежуточные реплики» | `/narration` |
| «Служебные файлы» | `/all-files` |
| «Скрыть блоки файлов» | `/no-files` |
| «Лимит результата» (Spinbox) | `/tool-limit N` (передаётся, если ≠ 4000) |
| «Без BOM» | `/no-bom` |
| «База (runtime.sqlite)» | `/db <путь>` (пусто = авто-поиск движком) |
| Язык (ru/en/zh) | локальный i18n + `/lang` движку (подписи в файлах) |
| «Открыть папку» | `explorer.exe /select,"<путь результата>"` |

Флаги-чекбоксы передаются только во включённом состоянии. `/api` передаётся всегда.

### 1.4 engine_client.py — контракт

- `engine_command() -> list[str]`: в разработке `[sys.executable, <корень>/backend/export_chat.py]`,
  в замороженном exe — `<рядом с GUI exe>/ExportChat-engine.exe`.
- `run_sync(argv, cwd, timeout) -> EngineResult{rc, stdout, stderr}`:
  `Popen(..., capture_output, text-пайпы utf-8/replace, creationflags=CREATE_NO_WINDOW)`.
- `build_env()`: копия окружения + `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8` (см. §1.5.1).
- `error_message(result) -> str`: rc=1 → `message` из stderr-JSON; rc=2 → текст stderr
  (уже человекочитаемый); пустой stderr → общее сообщение с кодом.
- `AsyncRunner.start(task, on_done)` / `is_busy` / `terminate()`.

### 1.5 Критические места и решения

1. **Кодировка stdout движка (главный риск).** Дочерний python на Windows пишет
   в пайп в локальной кодировке (cp1251): названия диалогов с не-cp1251 символами
   (китайский, эмодзи) исказятся — движок делает только `errors="replace"`.
   Решение: запуск с `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8` (только env со стороны GUI,
   движок не меняется); чтение пайпов — `utf-8`/`replace`. Ловится смоук-тестом шага 1, до UI.
2. **Мигание консоли**: `CREATE_NO_WINDOW` для дочернего процесса.
3. **Дедлоки пайпов**: `communicate()` в потоке; ответы движка короткие, правило общее.
4. **HiDPI**: `SetProcessDpiAwareness(1)` через ctypes до создания окна; проверка на 150 %.
5. **Чистая машина**: тест запуска GUI exe с пустым `PATH` (не зависит от системного Python).
6. **Идентичность CLI**: файл из GUI ≡ файл CLI при тех же опциях — `fc /b` на шаге 7.
7. **Папка AutoClaw**: никогда не пишем туда; все тесты — через копию `backend/`,
   вывод в `frontend/tests/_tmp/`; cwd движка — только папка вывода.
8. **SQLite из GUI** — запрещено (п.4.8 плана): базу читает только движок.

### 1.6 i18n

- `i18n.py`: `STRINGS{lang: {key: str}}`, `tr(key, **kw)`, `set_lang()`;
  ~70 строк на язык; ru — источник; тест: множества ключей ru/en/zh совпадают.
- Смена языка без перезапуска: `App._apply_language()` перепроставляет тексты всех
  виджетов, заголовков Treeview, окна; элементы не пересоздаются.
- Дата/время берутся из `/list` (`created_local`/`updated_local`) как есть.

### 1.7 Конфиг

- `%APPDATA%\AutoClaw\Z.ai-ExportChat-GUI\config.json` (fallback `~/AppData/Roaming`),
  атомарная запись (tmp + replace), `_version: 1`.
- Поля: `lang, output_dir, db_path, tools, narration, all_files, no_files, no_bom,
  tool_limit, window_geometry`.
- Дефолты: lang=ru, формат md, tool_limit=4000, чекбоксы выключены,
  папка вывода — `Документы\AutoClaw-Export` (создаётся при первом экспорте).
- Сохранение при каждом изменении и при закрытии.

## 3. Риски и меры

| Риск | Мера |
|---|---|
| cp1251-искажения из движка | `PYTHONUTF8=1`, ловится на шаге 1 — до написания UI |
| Ложные срабатывания антивируса на onefile | переключение на onedir в `build.bat` (одна строка) |
| БД не найдена на чистой машине | сообщение `err_no_db` движка показывается + поле `/db` |
| Долгий `/all` | неопределённый прогресс, окно живое, таймаут 600 с |
| Tk и потоки | одна задача за раз, `queue`+`after`, ноль вызовов Tk из потока |
| Экспорт «не туда» (cwd-трюк) | папка создаётся GUI заранее; путь результата берётся из JSON движка |

## 4. Открытые вопросы

1. **Git — решено (2026-11-07)**: репозиторий — проект пользователя (создан AutoClaw).
   Сейчас туда ничего не выкладывать. ZCode работает локально; когда рабочая версия
   будет готова, пользователь выдаст ключ доступа — ZCode сам выполнит push

   по циклу п.2 плана). Git на машине не установлен — к шагу 9 будет скачан
   PortableGit (портативная сборка, работает без установки и админ-прав), по согласованию.

## 5. Поставка: два exe или один (разъяснение)

> **РЕШЕНО (раунд 19, 2026-11-15):** сделан третий вариант — **полное слияние**:
> движки работают в процессе GUI (frontend/job_runner.py + backend/adapter.py),
> CLI удалён, поставка — один ExportChat.exe без CLI-режима. Ни «два exe»,
> ни «самозапуск с --zcode-engine-worker» не понадобились. Раздел сохранён
> как история решений.

Почему движок нельзя просто «вшить» в программу-окно: по контракту GUI обязан
запускать движок **отдельным процессом** (subprocess, JSON через stdout/stderr),
а читать базу SQLite напрямую GUI запрещено (п.4.8 плана). На машине пользователя
Python не установлен, поэтому каждый Python-компонент поставки должен быть
самодостаточным exe.

| | **«Два exe» (дефолт v1)** | **«Один exe»** |
|---|---|---|
| Файлы в zip | `ExportChat-GUI.exe` (окно) + `ExportChat-engine.exe` (невидимый помощник) | один `ExportChat.exe` |
| Размер | ~20–24 МБ | ~15–18 МБ |
| Как работает | окно запускает engine exe отдельным процессом | окно запускает **сам файл ещё раз** с невидимым флагом `--zcode-engine-worker`; в этом режиме тот же файл ведёт себя как движок (окно не создаётся) |
| Контракт | соблюдён (отдельный процесс, движок без изменений) | соблюдён (тот же отдельный процесс) |
| Smoke-тест движка (п.9) | напрямую: engine exe запускается в консоли сам по себе | только через GUI |
| Сложность | базовая | +30–50 строк диспетчера в `main.py` |
| Обновление движка | пересборка engine exe | пересборка единственного exe |

Оба варианта автоматизируются в `build.bat`; решение не окончательное —
начинаем с двух exe, «один exe» добавляется после v1 без переделки GUI.
